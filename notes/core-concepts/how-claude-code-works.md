## 한 줄 요약

Claude Code는 모델과 도구로 구성되어있고,  Claude에게 지시 대신 스스로 생각하게 하는 게 웬만한 상황에선 더 좋다.

## 읽기 전 내 예상

<!-- 반드시 읽기 전에 먼저 적을 것 -->

질문 -&gt; 응답을 기본 전제로 하고, 질문의 방향성에 따라 내부적인 Skill을 트리거하며 답변 품질을 올릴 것 같다.

## 문서 정리

모델은 당연하게도 Claude 모델을 이용하고, 코드와 전달받은 작업 내용을 보며 해야 할 작업에 대해 추론한다.

도구는 Claude Code를 에이전트로 만드는 것임. 도구가 없으면 Claude는 텍스트로만 응답할 수 있음. 하지만 도구가 있으면 Claude는 상호작용할 수 있음. 파일을 편집하고 명령을 실행하는 등의 행동이 가능해진다.

## 몰랐던 것 / 착각했던 것

문서를 읽어보니 큰 액션들은 크게 다르지 않은 것 같다. 다만, "질문 -&gt; 응답" 이라고 표현했던 다소 러프했던 동작을 쪼개서 설명한다 정도가 지식 보강의 차원으로 들어왔던 것 같다.



컨텍스트를 수집한다는 것이 내가 질문을 받았으니 거기에 필요한 기반 지식들을 모으겠다는 느낌으로 받아들이면 될 것 같네.



문서를 읽으며 보강가능했던 내용은 에이전트 루프는 두 가지 구성요소(모델, 도구)로 구성되어있단 점?



미세팁은 지시하지 말고 위임하는 게 더 좋단다.

지시는 "이거 이렇게 수정해."라고 아예 문제와 해결 방법을 제시해버리며 생각의 폭을 좁히는 건데, "이거 원인 조사하고 수정해줘."라고 위임을 하면 Claude가 세부 사항을 스스로 파악하게 되고 이게 좀 더 좋은 답변을 얻어낼 수 있다는 것임.

내가 지시하도록 많이 말 했던 것 같은데 이것도 위임하는 방향으로 사용 방식을 수정해볼 필요는 있겠다 싶음.
